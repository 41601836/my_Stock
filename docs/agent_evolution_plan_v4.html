1现有系统原理梳理

1.1 系统架构总览

当前 Agent 自主进化巡航系统是一个 暴力网格搜索 + 单目标优化 框架，核心流程如下：

┌──────────────────────────────────────────────────────────────┐ │ Agent 自主进化巡航系统 │ ├──────────────────────────────────────────────────────────────┤ │ │ │ 1. 生成 25 组因子组合 (从 24 个候选因子中随机拼装) │ │ └─ random.Random(42) 固定种子，3-5 因子/组 │ │ │ │ 2. 超参数网格: top_n = [20, 10, 30] │ │ └─ 25 组 × 3 档 = 75 个网格点 │ │ │ │ 3. 每个网格点执行完整流程: │ │ ├─ validate_factors() → IC 衰减校验 (VALID/WARNING/INVALID)│ │ ├─ search_new_factors() → 实验因子搜索 (IC > 0.025) │ │ └─ recommend_adaptive_portfolio() │ │ ├─ 原组合回测 (208 周) │ │ ├─ 新组合回测 (208 周) │ │ └─ 多状态路由回测 │ │ └─ excess_calmar_ratio = 超额年化收益 / |超额最大回撤| │ │ │ │ 4. 达标判定: excess_calmar >= 0.50 → 保存权重 + 写回 config │ │ 未达标 → 自动部署全局最优 (或稳健性闸门拦截) │ │ │ │ 5. 稳健性闸门: 同一组合三档 top_n 最小值 >= 0 才可入选 │ │ │ │ 熔断: max_loops=100 或 timeout=24h │ └──────────────────────────────────────────────────────────────┘

2问题诊断：为什么超额卡玛全为负？

从截图看，最近 10 次网格测试超额卡玛全部为负（-0.2885 ~ -0.3539），全局最优 -0.9684。这不是偶然的，是系统性问题：

🔴
因子空间陈旧、维度不足
24 个候选因子全是传统量价因子（动量、波动、换手率），没有利用 v3.1 新增的 15 个高维因子（Amihud 非流动性、GK 波动率、隔夜/日内分离、CYQ 筹码分布、板块强度、情绪复合）。因子间高度共线，信息增量为零。在当前市场环境下，传统量价因子已严重衰减。
🔴
搜索策略原始：纯随机网格
random.Random(42) 固定种子生成 25 组组合，没有任何自适应学习。不知道哪些因子组合方向好，每轮都从头开始。没有贝叶斯优化、遗传算法、或强化学习。75 个网格点对于 24 选 4-5 的组合空间（C(24,4)=10626）覆盖率不到 1%。
🟡
单目标优化，信息利用率低
只看 excess_calmar_ratio 一个指标。IC、ICIR、胜率、最大回撤深度、夏普比率等都被忽略。一个组合可能 IC 很高但卡玛为负（超额收益为正但回撤较大），直接被判死刑。没有多目标 Pareto 前沿。
🟡
无因子中性化
原始因子值未做行业/市值中性化。turnover_rate、pb 等因子在不同行业、不同市值的股票间差异巨大，不做中性化等于在做行业/市值暴露，不是纯 Alpha。P1 已经实现了 FactorNeutralizer 但 Agent 没有接入。
🟡
无共振策略整合
v3.1 已实现四重共振引擎（筹码×资金×板块×情绪），但 Agent 巡航完全不使用。共振策略的维度评分可以作为组合优化的多目标之一，但当前系统完全没有这个维度。
🟡
无防过拟合校验
P4 已实现 Purged Walk-Forward CV + IC 半衰期 + 三段审计，但 Agent 巡航不使用。208 周回测可能严重过拟合——在历史数据上找到的"最优"组合可能只是数据噪声。没有样本内外对比、没有置换检验。
🟡
EVO 层与 Agent 层割裂
EVO 进化层有动态权重、交叉因子、拥挤度、Graham 评分、LambdaRank ML、文本情绪等能力，但 Agent 巡航完全不调用这些。两套系统各自为战，EVO 的因子不在候选池里，Agent 的因子不在 EVO 表里。
🟡
回测周期过长
208 周 ≈ 4 年，跨越了 2022 年熊市、2023 年震荡、2024 年反弹等完全不同的市场环境。一个因子组合不可能在所有环境下都有效。应该分市场状态回测，或者缩短到 52-104 周。
🟡
前端展示信息单薄
Logs.jsx 只展示组合编号、top_n、超额卡玛三个字段。没有因子 IC、没有维度分解、没有净值曲线、没有与基准的对比图。用户无法判断"为什么这个组合不好"，只能看到"它不好"。

3进化建议与方案

3.1 总体思路

从 "暴力网格 + 单目标" 进化为 "智能搜索 + 多目标 + 防过拟合 + 可视化"：

当前: 随机 25 组 × 3 档 → 单一卡玛 → 达标/不达标 ↓ 进化: 智能搜索 → 多目标 Pareto → 防过拟合审计 → 共振加权 → 可视化 ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ 因子空间 │ │ 搜索算法 │ │ 评估体系 │ │ 前端展示 │ │ 24→40+ │ │ 随机→贝叶斯│ │ 单目标→多 │ │ 数字→图表 │ │ 无中性化 │ │ │ │ 无审计 │ │ │ │ →中性化 │ │ │ │ →三段审计 │ │ │ └──────────┘ └──────────┘ └──────────┘ └──────────┘

  • 修改 agent/config.yaml 的 experimental_pool 加入新因子
  • 回测引擎需要支持从 factor_values_evo 表加载 EVO 因子
E2: 因子中性化接入 — 剥离行业/市值暴露 P1 · 高优

在 validate_factors() 之后、recommend_adaptive_portfolio() 之前，插入中性化步骤：

validate_factors() ↓ 【新增】factor_lib.neutralizer.FactorNeutralizer.neutralize_cross_section() - 对每个因子做截面 OLS 回归: f ~ ln(free_mv) + industry_dummies - 取残差作为中性化后的因子值 - 消除行业/市值暴露 ↓ recommend_adaptive_portfolio() (使用中性化后的因子)
  • 已实现：factor_lib/neutralizer.py 的 FactorNeutralizer 类
  • 修改 agent/run_agent.py 的 run_single_full_process() 插入中性化步骤
  • 在 agent/config.yaml 新增 neutralize: enabled: true 开关
E3: 搜索算法升级 — 从随机网格到贝叶斯优化 P2 · 中优

用 Tree-structured Parzen Estimator (TPE) 替代纯随机网格：

  • 搜索空间：因子组合（离散）+ top_n（离散）+ multiplier（连续）
  • 替代方案：遗传算法（因子组合 = 染色体，excess_calmar = 适应度，交叉/变异/精英保留）
  • 混合策略：前 20 轮随机探索，之后切换到 TPE 利用
  • 收益：同样的 100 次测试预算下，找到好组合的概率提升 5-10 倍

实现方式：修改 run_auto_cruise() 的外循环，从遍历固定组合改为调用搜索器生成下一组候选。

E4: 多目标评估 — 从单一卡玛到 Pareto 前沿 P2 · 中优

将评估体系从单一 excess_calmar 升级为多指标加权评分：

指标权重说明
超额卡玛比率30%风险调整后超额收益（保留原有核心）
IC 均值20%因子预测能力
ICIR15%IC 的稳定性
超额胜率10%周度跑赢基准的频率
最大回撤10%绝对风险控制
共振维度分15%四重共振总分（v3.1 新增）

综合评分 = Σ(权重 × 归一化指标)，达标阈值从 0.50 调整为综合分 ≥ 60/100。

E5: 防过拟合审计接入 P2 · 中优

在达标判定后增加防过拟合审计环节，通过才可部署：

excess_calmar >= 0.50 ↓ 【新增】factor_lib.anti_overfit.AntiOverfitChecker.three_stage_audit() ├─ Stage 1: 经济逻辑 (方向一致 + IC显著 + 半衰期>2天) ├─ Stage 2: 统计验证 (置换检验 p<0.05 + 子周期稳定性>70%) └─ Stage 3: 样本外 (Purged WF-CV 正占比>60% + 衰减<60%) ↓ 三段全部通过 → 正式部署 任一段未通过 → 标记过拟合风险，降级或拒绝部署
  • 已实现：factor_lib/anti_overfit.py 的 purged_walk_forward()、ic_half_life()、three_stage_audit()
  • 修改 run_auto_cruise() 的达标判定块，插入三段审计
E6: 共振策略整合 — 四维评分作为组合优化维度 P3 · 低优

在推荐阶段引入四重共振评分，作为组合筛选的辅助维度：

  • 对回测选出的 Top-N 股票，计算四维共振分（筹码×资金×板块×情绪）
  • 共振分 > 0.7 的组合加权分额外 +10%
  • 共振分 < 0.3 的组合降权或剔除
  • 在日志中展示每个组合的四维雷达图

已实现：factor_lib/resonance.py 的 ResonanceEngine

Logs.jsx 升级展示内容：

E8: 回测周期分状态优化 P3 · 低优

将 208 周统一回测改为分市场状态回测：

  • 按市场状态（Range/Up/Down）分段回测，每段 52 周
  • 计算每个因子组合在不同状态下的表现
  • 最终评分 = 各状态加权平均（Range 权重最高，因为策略定位震荡市）
  • 展示分状态净值曲线，让用户看到组合在不同环境下的表现

4.2 总结

核心问题：当前系统"在一个小池塘里用随机撒网的方式找鱼"——因子池太小（24个传统量价因子），搜索方式太原始（固定种子随机组合），评估标准太单一（只看卡玛），且完全不使用已建好的高级能力（中性化、共振、防过拟合）。

核心对策：

  1. 扩大池塘（E1）：把 v3.1 的 15 个新因子 + EVO 交叉因子加入候选池
  2. 换智能渔网（E3）：从随机网格升级为贝叶斯优化/遗传算法
  3. 多维度评估（E4）：从单一卡玛升级为 IC+ICIR+胜率+共振多目标
  4. 接入已建能力（E2+E5+E6）：中性化、防过拟合审计、共振评分
  5. 可视化（E7）：从数字表格升级为图表仪表盘

建议先执行 P0（E1+E2），这两个改动最小但收益最大——把已有能力接入巡航系统，不需要写新算法。执行后重跑一轮巡航，大概率能看到正超额卡玛。
